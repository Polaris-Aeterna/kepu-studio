# 美术方向：从题材里长出来的动漫 / 游戏风

方法来自 taste-skill（`design-taste-frontend`），由《ETH 之墙》迁移到了视频帧上（见 `references/taste-for-video.md`）。核心三条：
1. **想法来自题材本身**：画风的装置必须承载题材自己的东西，否则只是一层皮。
2. **装饰禁令**：不要渐变、发光、阴影、紫色、霓虹、到处的细线框、编号 01/02、等宽小标签。
3. **去掉装饰以后要补实质**：主体放大、内容写全、用题材自己的图形、用整块色场，不能只剩“礼貌的空页面”。

## 装了 taste-skill 吗

按顺序找：
- `~/.claude/skills/design-taste-frontend/`
- `~/.claude/skills/taste-skill/`
- 环境变量 `TASTE_SKILL_DIR`
- 项目里的 `.claude/skills/*taste*`
- 作者给的路径

找到了，就读它的 `references/critique.md`、`tells.md`、`colour.md`、`type.md`、`motion.md`，网页规则以它为准，视频上的落地以 `references/taste-for-video.md` 为准。
没找到，就只用 `references/taste-for-video.md`：它是这些原则在视频上的浓缩版，足够用。

## 步骤

### 1. 盘点题材（不画任何东西）
在 `design/inventory.md` 里写 8–12 样只属于这个题材的东西：
- 核心对象（子句、变量、图、矩阵）；
- 关键数字（1.308ⁿ、800 篇论文）；
- 人和年代、标志性的动作（切一刀、数一数、交换求和顺序）；
- 这个题材自己的“印刷品”（论文首页、证明树、真值表）。
IDEA 就从这张清单里来。在 taste-skill 的盲测里，每个题目赢的都是从这种清单里长出来的页面。

### 2. 发牌（让脚本发，不要自己挑品类默认款）
```bash
./kepu art deal --subject "题材关键词" --n 4 [--engine anime|pixel]
./kepu art list                      # 全部 18 个方向
```
每个方向有：装置、IDEA 提示、配色 token、字体、签名动作、适合什么、风险。最近发过的会少发，换个系列不会总是同一套。

### 3. 每个方向写 IDEA 句，过竞品测试
> 在这个系列里，**[清单里的某样东西]** 变成 **[这个画风特有的装置]**。

例：“子句图的切口比特变成 Mini Metro 里过河的桥：桥越少，切得越便宜。”
**竞品测试**：把句子里的题材换成另一个科普题目（比如“傅里叶变换”）。句子仍然成立，说明这只是一层皮，换一个装置或者换一个方向。
每个方向还要写一张“比喻表”的草稿，列出题材里的东西各对应什么。游戏比喻是入口，不是定义。

### 4. 概念帧：每个方向两张
一张**标题卡**（章节标题、期号），一张**内容帧**（一个真实的知识点：公式加图，并且带字幕条）。
- 用最终的渲染器画。
  - anime 引擎：在 `engine/concepts/` 里按 `_kit.py` 的方式写，用 `FRAME=1 engine/render.sh` 出 PNG。仓库里有《ETH》六个方向的完整代码和总览图 `engine/concepts/concepts_overview.png`。
  - pixel 引擎：写一个只有一个场景的分镜，用 `--still` 出图。
- 内容帧必须装得下这个题材最难的画面，例如 6×6 矩阵、十几个节点的图、三行公式。装不下的方向直接淘汰。
- 拼成一张总览图给作者看，例如 3×2 网格，每个方向一行。

### 5. 打分：先自评，再请不是你画的评委
先按 `references/taste-for-video.md` §8 的格式逐张自评，然后派子 agent `kepu-studio:kepu-style-juror`。只给它图和 IDEA 句，不给你的结论，让它独立打分。
- **评分权重**：设计 40%，可用性（可读、清楚）30%，创意 20%，内容 10%。
- **封顶 6.5 分的情形**：出现渐变、发光、细线装饰、编号、等宽标签。
- **长片可持续性单独打分**：30 分钟、3 小时看下来会不会累。EVA 风的自评是 3/5，所以后来加了节奏系统。

### 6. 作者选定，落成系统
作者选了一个方向之后，写进 `series/系列设定.md` §4，并落成代码：
- **配色 token**：BG / SURFACE / INK / MUTED / ACCENT。代码里不出现裸 hex。强调色每屏最多一处。
- **字号**：三档，彼此差距大。展示 120–200，正文 36–44，小注 26–30（ManimGL 的 font_size）。
- **签名动作**：一个，每期 ≤ 3 次。其余动作都安静。
- **节奏预算**：大字卡每期 ≤ 8，插卡 ≤ 6，两次之间 ≥ 20 秒，镜头推拉 ≤ 2；冷开场可以放宽。最好让引擎自动计数并报警，ETH 的 `narrated.py` 已经这样做了。
- **四种时刻轮换**：内容时刻（约 80%）、大字时刻、插卡、白底或换底段落，给眼睛换口气。
- **字幕**：字幕是画面的一部分，字体、颜色属于这个画风，不是外挂的黑条。
- **anime 引擎**：照 `engine/style.py` 的接口重写配色和组件。`Display`、`Heading`、`CText`、`Formula`、`BigCard`、`InsertCard`、`cut_to`、`rise_in` 这些名字保持不变，场景代码就不用改。
- **pixel 引擎**：改 `pixel/engine.py` 顶部的调色板，在 `kit.py` 里加部件。

### 7. 封面（每期两种比例）
- 16:9 和 4:3 各排一版，不是裁切。避开播放量条和时长角标所在的区域。
- 封面文字是“谜题加搜索词”，不能说出本期要纠正的误解。
- 封面画风和片头章节卡一致，用同一套 token。

## 分镜（每期，配合画面阶段）

`script/storyboards/epNN.md` 的格式见该目录的 README：
- 每个 beat 写卡型、强调色落点、和稿子的“对应”（同，或者改编加理由）。
- 写清本期 IDEA 和节奏预算。
相邻 beat 不用同一种构图。画面变化发生在说到那个词的时刻。文字被念的时候，不要有东西从上面经过。
