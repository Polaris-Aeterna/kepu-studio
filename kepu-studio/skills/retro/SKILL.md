# 复盘：把每一次返工变成系统升级

元认知的最后一环。判断标准：同一类错误第二次出现，说明上一次只修了个例，没修系统。

## 1. 收集（看文件，不靠记忆）

把下面这些材料都翻一遍，列出这一期的每一件事故和每一次返工：
- `review/earcheck/epNN/status.json`，以及耳检结果里判“错”的条目；
- `review/epNN_*.md` 里的 🔴；
- 渲染日志里的警告：`WARNING [narrated]`、`WARNING [eva]`、遮挡检查的输出；
- `kepu gate` 的历史：哪一步卡住过；
- 花费：`kepu voice` 的输出里每次新合成的字符数，有没有为了返工重录；
- 作者在对话里指出的问题（时间、原话）。

## 2. 逐条追问

每件事故按“事 → 根子 → 以后 → 落在哪”写下来。“根子”一定要回答一个问题：**为什么没被更早的关卡拦住？** 常见的根子和对应的系统改动：

| 根子 | 系统改动 |
|---|---|
| 这个词不在词典里，模型猜错了 | 加进词典：项目层或个人层。对同学也有用的，记下来等会儿导出 |
| 规则判错了（例：“数完”误配进“计数完美”） | 改规则，并加回归测试：`toolkit/tests/test_pron.py` 的格式；或者放进项目的测试 |
| 检查器有盲区（例：遮挡检查漏了细字层） | 修检查器；拿已知的坏例子验证一遍；在全量上重跑 |
| 审稿没覆盖到某类错误（例：四舍五入制造的“进展”） | 写进 `review` 技能的 rubrics，或者写进本项目的审稿说明 |
| 画面的隐含约束（例：对话框最后画） | 写进引擎 README 的硬规则，最好再做成自动检查 |
| 分派说明不自包含，worker 各做各的 | 改分派说明的模板，加进范例 |
| 中间文件丢失，导致第二次运行失败 | 让这一步可以重复运行（幂等）：依赖不在就跳过，并说明 |

## 3. 落地

- **改文件**：词典、规则、检查、模板、README。
- **加回归测试**，然后跑 `./kepu selftest` 和 `./kepu lint script/episodes/*.md`，确认新规则没有误伤已经写好的稿子。
- **追加到 `LESSONS.md`**，写成四件事：事、根子、以后、落在哪。
- **分享给同学**：
  ```bash
  ./kepu lexicon export --scope user > 我的读音词条.tsv     # 个人层的读音决定
  ```
  同学收到后，把词条追加到自己的 `~/.kepu/lexicon.tsv`，或者项目的 `pron/lexicon.tsv`。对所有人都有用的规则或词条，也可以发给插件作者，合进下一版的内置词典。

## 4. 给作者的复盘报告（短）

- **这一期的数字**：
  - 时长；
  - 新合成字符数和返工字符数；
  - 耳检多少处、错几处；
  - 审稿 🔴 几条。
- **三条最值得记住的教训**，每条一句话，并写明系统改了什么。
- **下一期要特别注意的地方**：写进下一期的事故预演。
