# 审稿与审片

原则：
- **审稿的人不能是写稿的人。**派子 agent 去审，只给它材料，不给结论，避免它顺着作者的思路走。
- 每条意见都要能核对：标明哪个 beat、原文是什么、问题在哪、怎么改、出处是什么。
- 意见分三级：
  - 🔴 必改：事实或数学错误、误导；
  - 🟠 应改：讲不透、顺序乱、画面和讲的对不上；
  - 🟡 可改：措辞、节奏上的建议。

## 四个审稿子 agent（可以并行派）

| agent | 什么时候 | 给它什么 | 产出 |
|---|---|---|---|
| `kepu-studio:kepu-fact-checker` | 稿子写完，配音之前 | 稿子、讲义、`research/` 里的论文和资料、复算脚本 | `review/epNN_facts.md` |
| `kepu-studio:kepu-pedagogy-reviewer` | 稿子写完，配音之前 | 稿子、系列设定（观众、分级）、上一期稿子、`kepu stats` 的输出 | `review/epNN_pedagogy.md` |
| `kepu-studio:kepu-av-reviewer` | 每段渲染之后，以及成片之后 | 联系表、成片路径、.srt、引擎日志、`kepu gate` 的输出 | `review/epNN_av.md` |
| `kepu-studio:kepu-style-juror` | 定画风时；以及每期抽查 | 概念帧或联系表、IDEA 句、系列设定 §4 | `review/epNN_style.md` |

派的时候写清四件事：
- 文件路径；
- 本期“讲透的一件事”；
- 输出到哪个文件；
- 按 `references/rubrics.md` 的格式写。

审完汇总成 `review/epNN_SUMMARY.md`，内容是：
- 每个维度一句话总评，给出分数；
- 全部 🔴；
- 最值得改的前 10 条 🟠；
- 建议的修改顺序。

先改跨期连带的问题，再加新增的 beat，再调 beat 顺序，最后统一格式。

## 改完

- 🔴 必须清零。改完重跑 `./kepu lint`、`./kepu stats`、复算脚本。
- 改了台词就要重新配音，只重录改过的 beat，用 `kepu gate --stage voice` 查哪些不一致。
- 审稿发现的系统性问题，比如同一类数字错误出现了三次，记进 `LESSONS.md`，交给 `kepu-studio:retro` 去升级系统。

## 《ETH 之墙》审稿发现过的典型 🔴（以后先查这几类）

- **日期和“同一个星期”这类说法**：要和出处对上。两篇论文实际相隔 9 天。
- **四舍五入**：1.308 → 1.307 被写成了“进展”，其实 1.30704 一直没变。
- **pdftotext 把分数读坏**：4/9 被读成了“49”。数字都要回到 PDF 原页核对。
- **结论的范围**：把建立在别的假说上、其实没有倒下的结论，列成了“倒下的”（编辑距离）。
- **“只在 X 下成立”和“只在 X 下被证明”**：混用了这两种说法，是逻辑错误。
