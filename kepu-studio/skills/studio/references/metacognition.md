# 元认知：让流程自己发现自己的错，并且越用越好

“元认知”在这里是指：不光做事，还要持续问四个问题。
1. 我怎么知道这一步做对了？
2. 如果错了，最早会在哪里暴露？
3. 这个错误是个例，还是系统漏洞？
4. 修好以后，怎么保证它不再发生？

下面五个机制把这四个问题变成固定动作。

## 1. 事故预演（开工前，5 分钟）

在本期稿子的开头或 `review/epNN_premortem.md` 里，假设“这一期发布后被骂了”，写出最可能的 5 个原因，每个原因对应一个关卡：

| 可能的事故 | 早期信号 | 拦住它的关卡 |
|---|---|---|
| 某个领域词念错（例如 方差、相变、可数） | lint 的自动强制和拦下列表里出现新词 | `kepu lint` → 词典 → 耳检包 |
| 数字或日期错 | 稿子里有没出处的数字 | 事实账本 + `kepu-fact-checker` |
| 观众在第 8 分钟跟丢 | 连续 4 个 L2/L3 的 beat；超过 5 分钟没有提问 | `kepu stats` + `kepu-pedagogy-reviewer` |
| 字被盖住 / 出框 | 画面元素靠近字幕区 | 引擎的遮挡、出框检查 + 联系表 |
| 画风变成一层皮 | IDEA 句换个题目也成立 | 竞品测试 + `kepu-style-juror` |

对应不到任何关卡的，就是系统漏洞：加一条检查，或者加一条模板约束。

## 2. 决定账本（全程）

作者的每个偏好、每个读音、每个风格选择，都写进下表中的位置。新 session、子 agent、同学接手时，都从文件里读，不靠记忆。

| 决定 | 写在哪 | 谁读它 |
|---|---|---|
| 某个词怎么念 | `pron/lexicon.tsv`（只管本项目）或 `~/.kepu/lexicon.tsv`（所有项目共用） | `kepu lint` / `kepu voice` |
| 只管一处的读音 | 稿子里 `字〔读音〕` | 同上 |
| 希腊字母、替身字在某个音色上的验证结果 | `~/.kepu/voices/<音色>.json` | 同上；耳检包据此不再重复收录 |
| 画风、配色、节奏预算、比喻表 | `series/系列设定.md` | 写稿、分镜、渲染 |
| 每期标题 | `engine/episodes.json` 或像素引擎的 `title_screen` | 章节卡、下期卡 |
| 审稿结论 | `review/epNN_*.md` | 修稿、复盘 |
| 教训 | `LESSONS.md` | 所有人 |

## 3. 检查器校准（上线任何检查器之前）

- **先喂已知的坏例子**，确认它判得出来。
  - 例：作者否定过的录音。
  - 例：故意做坏的样本。
  - 例：`toolkit/tests/test_pron.py` 里的真实事故句。
- **再喂已知的好例子**，确认它不误报。
- **结果必须确定**：同样的输入，同样的输出。平票时不能靠 `set` 的顺序决定。
- **检查器的模型要和真实机制一致**：
  - 照引擎的画法检查。例：细字层永远在像素层上面。
  - 照缓存的全部来源检查，不能漏掉 `voice_ai/` 这类目录。
- 发现一个盲区，补上之后，**在全量上重跑一遍**。

kepu 的读音引擎就是这么校准的：
- 在两部作品的 5860 条旁白上跑，拦下的从 812 处降到 26 处，剩下的几乎都是真实的分词陷阱；
- 在《地基之下》第五轮审计的 537 处风险上，和审计结论一致的占 93%；不一致的是作者后来改定的“当成念 dāng”；
- 和 ETH 已经审定的读音逐处比对，找出了 ETH 现行词规则里一个潜伏的 bug：后来加的“数完”“数出”两条规则，会误配进“计数完美匹配”和“计数出发”，下次重录这两处就会念成 jìshǔ。成片是在这两条规则加入之前录的，念的是 shù，没有受影响。这类问题靠听成片是发现不了的，只能靠逐处比对。

## 4. 人的注意力只花在高风险处

- **耳朵**：只听耳检包（`kepu earcheck build`），不复听整集。
  - 收录：送拼音的、新替身字、还没验证过的希腊字母、低频词、缩写、数字，再加 5 处随机抽查。
- **眼睛**：
  - 看联系表：每个 beat 至少一帧。
  - 看遮挡、出框检查标出来的帧。
  - 不逐秒看成片。
- **作者的决定**：只问偏好题，例如读音选哪个、画风选哪个、措辞选哪个，每题都给候选。事实题和规则题由工具和子 agent 解决。

## 5. 复盘回路（每期结束，`kepu-studio:retro`）

每个事故按下面五步过一遍：
1. **事**：哪一期、哪一处、谁发现的。
2. **为什么没被更早的关卡拦住**：这是根子。
3. **系统改动**：从下面挑一种：
   - 加词条；
   - 加规则；
   - 加检查；
   - 改模板；
   - 改引擎默认值；
   - 改分派说明。
4. **回归测试**：把这个事故句加进测试，或者加进检查器的坏例子集。
5. **记账**：写进 `LESSONS.md`。对同学也有用的，导出词典补丁（`./kepu lexicon export --scope user`）。

判断标准：同一类错误第二次出现，说明上一次只修了个例，没修系统。
